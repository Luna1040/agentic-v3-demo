# 当前核心结构

## 前台：一次场景回复

turn-service 通过 execution-mode 选择明确的 streamDialogue 接口。宿主一次读取 ContextSnapshot，再由纯投影生成各角色背景/personality、压缩记忆、授权实体和时间信息。前台只接收本场人物包；服务保留的离场资料不能直接加入前台。

一个 Actor 生成完整第三人称场景，明确人物名字和行动主体。正常首字前没有 Main、Pulse、WorldOps。确需原句时可有界调用 read_dialogue，产生续写成本，是普通单次请求的显式例外。

commitDialogue 要求一条回复，保存正文、冻结输入、身份/时间来源及后台任务后立即 committed。后台失败不回滚消息。旧多 Actor 接口仅作兼容。

## 背景、证据与记忆

作者设定中的婚姻、共同历史和合理习惯本来就是背景，不要求重新发生才能承接。当前新增动作区分意图、进行和完成；说打算去不直接改变地点。真正矛盾、代替玩家同意、未执行的完成声明仍需阻止。

ContextSnapshot 统一读取；TurnEvidence 固定本轮来源；MemorySnapshot 带 throughSeq，防止摘要读取当前或未来回合。单场景正文的逐字人物片段带主体、位置和可见听众；公开言行可被在场角色记住，私密思想不广播。原文保留，压缩记忆不是唯一凭据。

新 NPC、地点和组织通过发现命令登记，需要原文证据及定义；计划里的人物不自动视为已遇见。

多人物作者卡通过导入时的 `source.cast` 生成独立身份，卡标题继续作为会话入口，不把整卡合并成一个人。旧世界的审核拆分、共同经历迁移与计划物品补记见 [多人物角色卡与旧数据修复](AUTHORED_CAST.md)。未执行物品事项以 `pendingIntent` 保留，不制造实物持有；后台更新另一个人物的记忆时使用该人物自己的资料包，不能用主角所见的裁剪身份覆盖作者资料。

## 后台队列

每世界按源回合顺序整理，最多合并三轮。新生产路径直接处理 v3 命令，不经过旧 review/patch 转换链。批内前项实体和事件以确定性投影传给后项；跨批由宿主事务与版本检查控制。

模型结果先保存检查点，再记录完成 trace。离线结果另存 receipt，避免日志失败后重复付费。依赖不变时复用结果，版本检查限定实际读取对象。失败最多自动尝试三次后等待重试；原文和任务不静默丢弃。

队列不保证无限吞吐。长期输入快于整理仍会落后；失败前项可能阻挡后项，界面必须显示积压和重试入口。

## 事件归并

WorldOps 从现有账本选择 new / link / no_change，状态是 planned / in_progress / completed / cancelled。只有新的发生才创建新事件；反复提及同一行程不重复移动，重复提交不重复产生副作用。

独立有效命令可提交，无效候选进入 deferredCommands；dependencyGroup 整组成功或整组待处理。待处理不是事实，也不撤销其他有效记忆。协议见 Harness apps/agentic-v3/EVENTS.md。

2026-10-26 全链路核查及自然对话结果见 [记忆入库链路检查](MEMORY_PIPELINE_AUDIT.md)。同轮 reducer 使用已接受工作态，批内按人物投影版本；WorldOps 工具 ID 使用服务获准资料并集，实际写入仍受各人的版本和知情范围限制。新建/更新分支明确区分，无变化用不携带阶段的 unchanged。处理结束但候选未应用时保留按需读取索引并显示待核对；已省略来源通过 source_gap 明确标记。

语义关联仍依赖模型选择已有事件。代码只对明显相同的开放摘要保守去重。同轮可用 new:key 引用此前已接受的地点发现；跨轮同批尚不可用的引用保留待处理，不编造 ID，不自动整批拆成额外付费请求。独立记忆和实体发现不能被无关物理变化的失败连带撤回。

## 跨多轮主线

Main 维护阶段、完成条件和总轮数预算，通常以十轮内的事件为目标。有效计划复用；阶段完成、用户转向、到期或失效再规划。每世界只有最新请求，过时结果不覆盖新剧情。

Actor 立即顺应用户拒绝，无须等 Main。计划是创作建议，不能充当已发生事实。WorldOps 的 storyProgress 提供有来源的进展；计划与实体事实分开存储。

## 时间与离线

UTC记录、界面本地时间、故事时间分别保存。离线按源回合冻结时间和位置结算，再整理当前回合；不重复推进时钟，不给未处理人物推进游标。活跃场景不会因请求等待自动跳时。没有空闲 world_ticks 或无人互动时持续模型调用。

## 接手入口

| 层 | 入口 | 责任 |
| --- | --- | --- |
| Harness应用 | scene-response / mainline / event-reducer / stage-runner | 模型协议、场景正文与事件归并 |
| 宿主服务 | turn-service / settlement-worker / director | 前台生命周期、后台任务 |
| 存储 | store / context-snapshot（含记忆快照） | 授权快照、来源、事务、版本与恢复 |
| 客户端 | conversation-controller / conversation-state | 单条流式、断流恢复、背景刷新隔离 |

应用类型和时间规则由 harness:build 生成到 .harness-contract，禁止双份手写；公共 Harness SDK 未因本次业务改造修改。迁移014增加快照/事件账本，015增加离线 receipt，016保存失败重试的运行版本历史。旧会话和角色卡保留，不批量改写旧记忆。

只有尚未产生模型结果、正文或检查点的失败轮次，才允许升级运行版本后沿用原请求编号重试。传输诊断与原文读取不算已生成正文。若版本变化源于前一轮归档晚到，且没有后续消息、场景或身份变化，可保留原输入到审计历史后刷新上下文重试；其他版本冲突继续拒绝。不重复插入玩家消息，已有模型结果不能静默跨配置继续执行。前台开始时锁定规划请求并取消过时的运行资格，晚到的 Main 不能替换本轮正在使用的计划。

地点未知时，WorldOps 另行返回 sceneContext，区分确立当前所在场所与移动。确立地点需当轮外显原文、已登记地点及空间关系；不增加旅行事件。宿主仅在该回合仍是最新场景时补齐位置，晚到结果不能覆盖新场景。

旧入口及 legacy-ops 仍保留兼容；不能把本次称为删除了所有旧代码。历史 pipeline 文档仅用于追溯。
