# 记忆入库链路检查与修复（2026-10-26）

核查范围为当轮来源提取、WorldOps 工具合同、纯 reducer、同批归并、数据库事务、人物知识快照、压缩记忆与下轮读取。人物/地点/物品/约定已有独立实体表；人物摘要本身不会删除这些实体。实际风险集中在漏提取、后命令从旧工作态重建字段、错误权限投影和恢复索引缺失。

| 已确认根因 | 本次修复 |
| --- | --- |
| 同轮 patch 只合并输出，后续命令仍读取旧实体，约定 nextStep/description 可退回旧值 | 每个已接受 patch 同步工作态，保留原 baseVersion 做一次事务 CAS |
| 批内只更新根包，第二人物仍用旧自有版本，合法记忆被拒 | 各人物包分别承接获准的实体、摘要、版本；私人记忆不广播 |
| 物品/约定新建与更新混成可选字段，真实模型误认为有 ID 枚举就不能再新建 | 明确 create/update 分支；新建 key/name 必填，更新必须用对应 ID |
| 两人分别答应同名约定，被全局同名去重吞掉一人的责任 | 约定身份按名称与责任人共同判重；同一人重复仍拒绝 |
| 后台工具只列主角色可见 ID，另一个人物自己的约定虽然存在却无法修改 | 服务工具按当前人物的授权资料并集提供 ID，写入仍选择对应责任人/来源人的版本；不将服务参考广播到前台知识 |
| 没有状态变化时仍重新填写事件阶段，可能串用别人的事件 ID | 使用只含实体 ID 的 unchanged 审查，不改阶段或状态；旧候选继续兼容并检查事件归属 |
| 合并摘要超过窗口或来源片段被省略后，completed 移除了未处理索引 | source_gap 和未应用候选保留按人物权限的 pendingTurnIds；界面单列数量，不把候选当事实 |
| 模型用 defer 解释无法保存实际变化，表面却显示全部归档 | actual_action 类型 defer 同样算未应用；普通未决定提议继续单独处理 |
| 重见场景/移动时整份记忆快照刷新，可能把旧私密地点状态广播给后来者 | 场景重见仅同步可观察身份和位置；明确见证的新变化生成部分快照 |
| 旧见证者错过一次私密版本后，后续公开变化也永远拿不到 | 只叠加本次公开改动；从部分快照写回时递归合并，保留真实状态中未见过的字段与里程碑 |
| 最近100条终态历史挤掉旧开放事件 ID，后续无法 link | 开放事项优先，仍保持100条窗口；超过窗口明确显示溢出，不假定旧事项已完成 |
| 新计划物品取消或完成后仍显示待执行 | 同步意图生命周期，保留真实持有与地点状态的独立性 |

前台仍是一条 Actor 流式消息，没有增加常驻审核模型或首字前的 Main 调用。后台在同一次 WorldOps 中提出原子命令；摘要提及不等于结构化建档，当前实体与账本优先于旧摘要。

相关回归包括 Harness event-reducer/batch/scene，以及宿主 `host-memory-index`、`observed-patch`、`backend-temporal-knowledge`、`authored-cast`、`core-rewrite` 等真实 PostgreSQL 测试。
