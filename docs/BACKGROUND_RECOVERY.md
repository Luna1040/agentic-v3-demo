# 后台时间校验与排队场景恢复

后台整理按世界顺序执行。一轮失败达到重试上限后，同世界后续回合保持等待；前台回复已保存不代表后台归档已完成。

## 修复的三处边界

- 前台持久化的剧情时间保留原始来源引文，Actor 时间快照不携带该引文。后台从源回合冻结的输入重新计算时间，核对时间及来源身份，再保留已提交的完整来源；不把继承的旧引文当成本轮时间推进。后台结果不能修改既定时钟。
- 较早回合的归档会增加世界版本号。最新回合的地点补齐或移动不能仅因这些归档而被认定过时：在场景内容一致、场景最后写入时间不晚于源回合提交时允许应用。仍要求源回合为最新已提交回合；手动确认相同场景也通过数据库时间戳阻止旧结果覆盖。
- 已有地点时，用户明确请求“快进到那天”等切场，正文已确认新场所和主角色在场，可以通过匹配的 Harness 应用确立新场景，不需要补写走路动作。新场所必须先登记，只更新有证据的主角色，不凭空推进时间或制造旅行事件。共享的 `scene-cut` 纯规则由构建产物生成，不在宿主重复维护。

## 验证与恢复

新增回归位于 `test/settlement-inherited-time.test.ts`，覆盖继承时间后连续归档、拒绝错误时钟、积压后最新地点补齐，以及同值手动场景确认的保护。结合现有 settlement、temporal、core 和七轮积压回归验证。测试使用独立 PostgreSQL 测试库和假模型。

`test/scene-cut.test.ts` 使用实际 Harness reducer 和独立测试库验证阶梯教室到咖啡馆的切场，以及手动场景和后续回合保护。

本补丁不需要数据库迁移，但切场支持需要匹配的 Harness 应用。先审阅并构建 Harness 源码分支，再更新完整匹配的运行产物、`.harness-contract` 和锁定文件；不要只复制某个 JS 文件或改旧构建标识。按 `GIT_WORKFLOW.md` 部署并确认健康后，可在世界状态界面重试失败的后台整理。重试可能产生真实后台模型调用；不能通过改写历史对话、手工伪造地点或跳过失败队首替代恢复。

切场只可写入仍对应最新回合的场景。已积压的历史切场不能覆盖后来消息；这些历史数据需单独核对，不保证仅重试队列就能自动修正当前地点。

已有未应用候选不会自动变成事实。若地点发现因原文不含名称、引用错误、仅有计划或回忆而被拒绝，应继续核对 Harness 的证据选择与场景确立逻辑；本补丁不放宽这些语义校验，也不自动重放历史候选。
